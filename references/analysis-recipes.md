# 分析配方库

先确定问题属于哪一类，再选配方。漫无目的地 `describe()` 不是分析。

---

## 零、先分清你在做哪件事

Google 首任首席决策科学家 Cassie Kozyrkov 的区分，这是所有分析的前提：

| | 探索（analytics） | 推断（statistics） |
|---|---|---|
| 在做什么 | 看数据里**有什么** | 推断数据**之外**的东西 |
| 产出 | 好问题、假设、灵感 | 可对外声称的答案 |
| 卓越标准 | 速度 | 严谨 |
| 措辞 | 「数据里看到…这值得查一下」 | 「有证据表明…」 |

**红线：不能用同一份数据既生成假设又验证假设。**
你在一份数据里翻找，找到一个「渠道 C 在周三转化特别高」的规律——
这是探索的产出，是个问题，不是结论。要变成结论，需要新的数据。

违反这条的后果不是「不够严谨」，是**任何噪音都能被讲成规律**。
一份随机数据，切二十个维度，总会有一个看起来显著。

在报告里必须区分这两种措辞。把探索发现写成推断结论，是最常见的数据欺诈，
而且做的人通常没意识到自己在欺诈。

---

## 一、对比：A 和 B 谁高

**先问三件事**：可比吗（口径一致吗）、差异多大（绝对值多少）、这个差异稳定吗（换个时间窗还成立吗）。

```python
g = df.groupby("渠道")["销售额"].agg(["sum", "median", "count"])
g["占比"] = g["sum"] / g["sum"].sum()
g.sort_values("sum", ascending=False)
```

给 `count` 是必须的——只有 3 个样本的渠道，它的均值不能和有 3000 个样本的渠道并排比较。

**陷阱 · 基数太小**
从 2 涨到 6 写成「增长 200%」很唬人，但它就是 4 个。
**基数小于 30 时给绝对值，不给百分比。** 这条要写死。

**陷阱 · 辛普森悖论**
每个分组内 A 都优于 B，合起来却 B 优于 A。经典案例是 1973 年 UC Berkeley
录取率案：整体上女性录取率低于男性，看起来是性别歧视；
但拆到每个院系，女性录取率反而普遍高于男性——
真实原因是女性更多申请了竞争激烈、录取率本就低的院系。

**所以看总量必须同时看分组：**

```python
overall = df.groupby("组")["转化率"].mean()
by_seg  = df.groupby(["细分", "组"])["转化率"].mean().unstack()
# 两个方向的结论一致吗？不一致就是辛普森悖论，要报告分组结果而不是总量
```

不一致时，**分组结果通常才是对的**，总量被样本构成差异污染了。

## 二、趋势：在变好还是变坏

```python
ts = df.set_index("日期").resample("D")["销售额"].sum()
```

**必做的第一件事是查断点。** 缺失的日期不会报错，但会让趋势线撒谎：

```python
full = pd.date_range(ts.index.min(), ts.index.max(), freq="D")
missing = full.difference(ts.index)
print(f"缺失 {len(missing)} 天：{list(missing[:10])}")
```

**陷阱 · 周期性**
日粒度的业务数据几乎都有周内周期（周末高或周末低）。
不做处理直接看日环比，得到的全是星期几的噪音。
用 7 日移动平均，或者同比同一天（周一比周一）。

```python
ts.rolling(7, center=True).mean()
```

**陷阱 · 不完整的最后一期**
本月只过了 12 天，月度汇总里的最新一个点必然是低的，看起来像断崖下跌。
**画趋势时把不完整的期次去掉或明确标注。** 这个错误极其常见。

**陷阱 · 回归均值**
上期表现最好的门店这期变差了，往往不是策略失效，是统计规律：
极端值下一期倾向于回归平均。
识别方法：如果「上期最好的一批」和「上期最差的一批」这期都向中间移动，
那就是回归均值，不是你的干预起了作用。

**陷阱 · 起点选择**
从哪一天开始画，能得出完全相反的结论。
起点必须有业务理由（财年初、改版日），不能是「从这里开始看起来最好」。

## 三、构成：钱从哪来

```python
comp = df.groupby("品类")["销售额"].sum().sort_values(ascending=False)
comp_pct = comp / comp.sum()
cum = comp_pct.cumsum()
print(f"前 {(cum <= 0.8).sum() + 1} 个品类贡献了 80%")
```

**陷阱 · 构成变化 vs 总量变化**
「A 品类占比从 30% 降到 20%」——A 可能销售额没变，是别的品类涨了。
**占比和绝对值必须一起给**，只给占比是误导。

**陷阱 · 负值**
有退款、亏损时，占比会出现负数和大于 100% 的值，饼图直接失效。
这时候用瀑布图或者分开呈现正负。

## 四、分布：典型情况是什么样

**默认给五数概括，不给均值**（Tukey 的抗差统计）：

```python
s.describe(percentiles=[.05, .25, .5, .75, .95])
```

业务数据几乎总是右偏：少数大客户贡献大部分收入，少数爆款贡献大部分销量。
这时候均值大于中位数，而且均值描述的不是任何一个真实客户。

**判断偏态**：均值明显大于中位数 → 右偏 → 用中位数描述「典型」。

**陷阱 · 用均值描述偏态分布**
「人均消费 800 元」——如果中位数是 200，那 800 是被几个大客户拉出来的，
没有任何一个「平均用户」长这样。说「一半的用户消费低于 200 元」才是真实的。

**陷阱 · 平均数掩盖双峰**
两群完全不同的用户混在一起，均值落在中间的谷底，描述的是不存在的人。
画一下直方图，看看是不是双峰。

## 五、异常：哪里不对劲

```python
q1, q3 = s.quantile([.25, .75])
iqr = q3 - q1
out = s[(s < q1 - 1.5*iqr) | (s > q3 + 1.5*iqr)]
```

**Twyman's Law：任何看起来有趣或异常的数字，通常都是错的。**
被称为整个数据分析领域最重要的单条定律。

所以异常值的默认假设是「数据错了」，不是「发现了洞察」。逐个排查：

1. 单位错了吗（这一行是元，其他行是万元）
2. 多打了一个零吗
3. 是汇总行混进来了吗
4. 是测试数据吗（金额 1 分、名字叫「测试」）
5. 以上都不是 → 才是真实的业务异常，值得深挖

**不要自动删除异常值。** 删之前必须知道它为什么异常。
黑天鹅事件、大客户、爆款都会表现为异常值，删掉它们等于删掉最重要的信息。

## 六、相关：X 和 Y 有关系吗

```python
df[["投放费用", "销售额"]].corr(method="spearman")
```

用 **Spearman 秩相关** 而不是 Pearson：Pearson 只测线性关系，
且对离群值极度敏感——一个异常点能把相关系数从 0.1 拉到 0.8。

**陷阱 · 相关不是因果**
这条人人都会说，但落到具体分析里照样犯。
「用了优惠券的用户复购率高」——是优惠券带来复购，
还是本来就打算复购的人才会去领优惠券？

**能区分的唯一办法是实验**（随机分配），观察数据分不出来。
如果没有实验，措辞必须停在「相关」，不能滑向「带来」「提升」「导致」。

**陷阱 · 幸存者偏差**
只统计还活着的样本，结论系统性偏乐观。
「用了我们产品的公司平均增长 30%」——倒闭的那些不在你的数据里。
分析留存、复购、成功率时，先问：**哪些样本因为失败而从数据里消失了？**

## 七、漏斗：在哪一步流失

```python
steps = ["曝光", "点击", "加购", "下单", "支付"]
n = [df[s].sum() for s in steps]
for i in range(1, len(steps)):
    print(f"{steps[i-1]}→{steps[i]}: {n[i]/n[i-1]:.1%}  流失 {n[i-1]-n[i]:,}")
```

**陷阱 · 时间窗口**
今天曝光的人可能明天才下单。用同一天的数据算转化率，会系统性低估。
正确做法是**按用户追踪**（这批人在 N 天内的转化），不是按天横切。

**陷阱 · 分母口径**
每一步的转化率，分母是上一步还是最初的曝光？两种都合理，但必须声明，
而且全文保持一致。混用是最常见的漏斗分析错误。

## 八、留存：用户留下来了吗

按注册批次（cohort）看，绝不能看整体：

```python
df["批次"] = df["注册日"].dt.to_period("M")
df["月龄"] = (df["活跃日"].dt.to_period("M") - df["批次"]).apply(lambda x: x.n)
cohort = df.pivot_table(index="批次", columns="月龄",
                        values="用户ID", aggfunc="nunique")
retention = cohort.div(cohort[0], axis=0)
```

**陷阱 · 整体留存率被新用户稀释**
大量新用户涌入会让整体留存率看起来在下降，即使每个批次的留存都在改善。
这是辛普森悖论在留存分析里的形态。

**陷阱 · 最新批次的数据不完整**
最新一个月的批次只有 1 个月龄的数据，右下角那片三角区是空的，不是 0。
画热力图时必须把不完整的格子留白，填 0 会画出一条假的断崖。

## 九、归因：功劳算谁的

这是最容易出错的一类，因为「正确答案」取决于你选的归因模型，而模型是假设不是事实。

常见模型：末次点击、首次点击、线性平均、时间衰减、位置加权。

**同一份数据，不同模型能得出完全相反的渠道排名。**

所以归因分析的正确交付方式是：**给出至少两个模型的结果，并说明差异**。
只给一个模型的结果、不说用了什么模型，等于隐瞒了最关键的假设。

```python
# 末次点击 vs 首次点击，看排名是否稳定
last  = df.sort_values("时间").groupby("用户ID").last()["渠道"].value_counts()
first = df.sort_values("时间").groupby("用户ID").first()["渠道"].value_counts()
pd.DataFrame({"末次": last, "首次": first})
```

两个排名差别很大时，说明渠道在链路中的位置不同（有的负责拉新、有的负责收口），
这个差别本身就是最有价值的发现。

## 结论的措辞标准

证据强度决定措辞强度。

| 证据 | 能说什么 | 不能说什么 |
|---|---|---|
| 单次观察、无对照 | 「这批数据里 A 比 B 高」 | 「A 比 B 好」 |
| 多期一致、无对照 | 「A 持续高于 B」 | 「A 导致了…」 |
| 有对照的实验 | 「A 带来了 X% 的提升」 | 「A 一定会带来…」 |
| 相关分析 | 「X 与 Y 相关」 | 「X 提升了 Y」 |

**样本量小于 30 时**，任何百分比都要同时给绝对数。

**不确定的时候，把不确定写进句子里**，不要用一个确定的句子加一句免责声明。
「大概率是渠道 C 的问题，但我只有两周数据，换个窗口可能就不成立」——
这样写比「渠道 C 是主要问题（注：样本有限）」诚实得多。
