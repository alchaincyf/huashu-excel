# xlsx 交付物的排版

这份文件管**你交出去的 xlsx 长什么样**。

别人给你的脏表怎么读、怎么洗，在 `dirty-data.md`；
Excel 公式怎么写、有哪些坑，在 `excel-craft.md`；
报告的设计怎么定，在 `report-styles.md`——那份文件说的每一条对 xlsx 一样成立，
这份只补 xlsx 独有的落法。

---

## 一、xlsx 不是导出的副产品

模型有个默认动作：HTML 是「设计出来的」，xlsx 是「导出来的」。
于是同一份分析，HTML 那份有配色有层次有节奏，xlsx 那份是一列黑字。

**它们是同一份设计计划的两种落法。** 读者拿到 xlsx 不会因为它是 Excel
就降低期待——恰恰相反，他打开 xlsx 是因为他要在里面**继续动手**，
这份东西会被他看得比 HTML 更久。

`report-styles.md` 第二节要求写第一行 HTML 之前先落设计计划（Color / Type /
Numerals / Space / Layout）。**那份计划同样是 xlsx 的施工图**，不用重写一份：
Color 的 token 变成字色与填充色，Numerals 变成 `number_format`，
Space 变成行高与列宽，Layout 变成合并区域与冻结窗格。

### 「xlsx 必须走脚本」只对图表成立

手写 openpyxl 的图表 API 确实不划算——那句话是对的。
但**排版不是图表**。合并、行高、列宽、字色、填充、数字格式，
每一样都是三五行代码，而且只有手写才能对得上设计计划。

所以分工是：**图表交给 `make_report.py` / `make_chart.py`，排版自己写。**
把「必须走脚本」从图表扩大到整份文件，结果就是一套无名兜底缺省值渲染出来的东西，
它不认识你的读者，也不认识这份数据。

---

## 二、先分清两种 sheet，规则几乎相反

一份交付用的工作簿通常至少两张表，它们要用两套完全不同的排版：

| | **报告 sheet** | **数据 sheet** |
|---|---|---|
| 一个单元格装什么 | 一段话、一个 KPI、一个小节标题 | 一个字段值 |
| 读者拿它干什么 | 从上往下读 | 排序、筛选、透视、下钻 |
| 合并单元格 | **该用**（见第三节） | **禁用** |
| 换行 | `wrap_text=True` 是常态 | 基本不用 |
| 行高 | 按内容算 | 统一默认高度 |
| 填充色 | 用来分区块 | 只用在表头 |
| 冻结窗格 | 一般不需要 | **必须有** |
| 自动筛选 | 不加 | 加 |

**`excel-craft.md` 第三节那条「合并单元格会破坏排序、筛选、透视」说的是数据 sheet。**
它是对的，但只对那一半成立。把它套到报告 sheet 上，
就会得到一份所有正文都挤在一列里、靠溢出往右显示的东西——
而溢出一旦撞上右边有内容的单元格，文字就被硬生生切断。

**判据很简单：这个单元格里的东西，有人会拿去排序吗？**
不会，就该合并。

---

## 三、合并单元格：报告 sheet 里是主力

报告 sheet 里的标题、副标题、小节标题、正文段落、脚注，
**一律合并到内容区全宽**（比如 `B2:G2`），不要只放在 B 列靠溢出。

三个理由，一个比一个实际：

1. **溢出会被挡住。** 右边任何一个单元格有内容，文字就在那里截断。
   最典型的翻车：正文段落在 B 列靠溢出显示得好好的，
   直到某一行右边放了个 KPI 数值，那一段就被腰斩。
2. **`wrap_text` 需要一个真实的宽度才知道在哪换行。** 不合并的话，
   它按 B 列那一列的宽度换行，而你眼睛看到的是横跨 B 到 G 的一整条。
   于是行高按一列宽算、文字按七列宽显示，两边对不上。
3. **合并区域是一个可测量的容器**，行高才算得准（见下一节）。

**合并前清空被吃掉的格子。** 合并只保留左上角单元格的值，
其余静默丢弃——先写值再合并会丢数据，先合并再写值才对。

**KPI 区尤其要小心。** 一个「标签在上、数值在下」的 KPI 条，
数值往往是 16pt 以上的粗体，宽度远超一列。
每个 KPI 各自合并成一个固定宽度的块（比如三个 KPI 各占 `B:C` / `D:E` / `F:G`），
让标签和数值**共用同一个合并宽度**——否则标签在 C 列、数值溢出到 D 列，
两者视觉上对不齐，读者要猜哪个数配哪个标签。

## 四、行高：算出来的，不是从档位里挑的

**这是 xlsx 排版最主要的单一错误来源。**

模型的默认动作是从一组看起来合理的档位里挑一个——`16 / 30 / 45 / 60`
之类。结果是：18pt 的粗体大标题配了 16 磅行高，字上下被切掉；
一段 70 字的正文 wrap 成三行却只给了 30 磅，底部一整行看不见。

**这类错在屏幕上很容易被忽略**（滚动时一扫而过），但读者一眼就看见，
打印出来更是明摆着。

### 算法

```python
import math

# 经验常数，集中在一处方便调
LINE_HEIGHT_RATIO = 1.4    # 单行高度 ≈ 字号 × 1.4（磅）
CELL_PADDING_PT   = 2.0    # 上下内边距
BASE_FONT_SZ      = 11.0   # 列宽单位是按 11pt 标定的

def visual_len(s: str) -> float:
    """中文/全角按 2 个单位，其余按 1 个。"""
    return sum(2 if ord(ch) > 0x2E80 else 1 for ch in s)

def need_height(text: str, total_width: float, font_sz: float = 11.0) -> float:
    """total_width = 该单元格（或合并区域）所有列的列宽之和"""
    # 字号越大，同样列宽装得下的字越少
    cap = max(total_width * (BASE_FONT_SZ / font_sz), 1.0)
    lines = 0
    for para in str(text).split("\n"):        # 显式换行符要分段各算各的
        lines += max(1, math.ceil(visual_len(para) / cap))
    return lines * font_sz * LINE_HEIGHT_RATIO + CELL_PADDING_PT
```

**这是估算不是精算**——真实换行取决于字体度量，openpyxl 拿不到。
所以**宁可高一点**：多出来的几磅只是留白，少了就是文字被裁。

**不设 `wrap_text=True` 的单元格不要算这个**，它不换行，
一行的高度够就行；但它会溢出，回到第三节的问题。

### 空行是间距，不是遗漏

xlsx 没有 `margin`，节与节之间的呼吸靠**空行 + 行高**。
`report-styles.md` 定的间距刻度在这里落成空行的高度：
小节之间给一个 12 磅的空行，大节之间给一个 20 磅的，不要一律用默认的 15。

## 五、列宽与数字格式

**列宽先定用途再定值。** 报告 sheet 的内容列（合并后的总宽）
对应 HTML 里的版心——中文每行 38 到 42 字最舒服，
折算成列宽单位约 76 到 84。
数据 sheet 的列宽按该列最长值算，加两个字符余量。

**A 列留一个宽度 2 的窄列当左边距**，让内容不贴着窗口边——
这个做法是对的，别因为它看起来「浪费一列」就去掉。

### 数字必须设 number_format

单元格里存 `9351342.370000001` 而 `number_format` 是 `General`，
Excel 就会把那一长串原样显示出来。**这不是显示 bug，是没设格式。**

```python
cell.value = 9351342.37          # 底层值保持精确，不要 round()
cell.number_format = '#,##0.00'  # 显示层控制小数位
```

常用格式串：

| 场景 | 格式串 |
|---|---|
| 金额（整数） | `'#,##0'` |
| 金额（两位小数） | `'#,##0.00'` |
| 带币种 | `'£#,##0'` / `'¥#,##0.00'` |
| 百分比（一位小数） | `'0.0%'`（**值要存 0.058 不是 5.8**） |
| 负数用括号 | `'#,##0;(#,##0)'` |
| 日期 | `'yyyy-mm-dd'` |

`report-styles.md` 第四节那几条（同列小数位统一、千分位、单位进表头、
负数表示法全篇一致、数字列右对齐）在 xlsx 里逐条照用。
**openpyxl 里数值默认就是右对齐**——别手贱把它设成居中。

**列宽不够时 Excel 显示 `####`。** 数值按格式渲染后的字符串长度
（含千分位、币种符号、负号）要能装进列宽，
大字号的 KPI 尤其容易撞线。

## 六、色彩：xlsx 多了一种 HTML 没有的手段

xlsx 的字色用法和 HTML 一样，但它多了**填充色**——
整行整块地铺底色，这是 xlsx 分区最有效的工具，也是最容易滥用的。

**颜色全部从设计计划的 token 派生**，不要在 xlsx 里另开一套。
`report-styles.md` 第六节「三套颜色各管各的」在这里同样成立。

四条落法：

- **表头** = 深色填充 + 反白粗体字，或浅色填充 + 墨色粗体字。选一种，全簿一致。
- **区块分隔** 用极浅的填充（token 里那个 `--wash` 一级的颜色）铺整行，
  不要用边框画框——xlsx 里的框线一多就像财务报表模板。
- **斑马纹**只在数据 sheet 用，且只在超过 20 行时用。报告 sheet 不用。
- **语义色**（正 / 负）通过条件格式或 `number_format` 的颜色段实现，
  比如 `'#,##0;[Red]-#,##0'`。

### 同级别的东西必须长得一样

这是 xlsx 里最常见的层级事故：七个小节标题都是 13pt 粗体，
其中两个用了强调色，另外五个是墨色。**读者跟的是视觉，不是你的意图**——
他会以为那两个是更高一级。

写完之后做一次机械自查：把所有单元格按 `(字号, 是否粗体)` 分组，
同一组里出现两种以上字色，就是层级漏了。

## 七、数据 sheet 的四条底线

给人「继续动手」的那张表，反而最容易被裸着交出去：没列宽、没表头样式、
没冻结、没筛选。它是全簿最实用的一张，别让它最难用。

1. **首行冻结**（`ws.freeze_panes = "A2"`），左侧有标识列时冻结到 `B2`。
   **注意冻结点要落在真实内容上**——内容从 B2 开始却冻结 A2，
   冻的是一行空白，等于没冻。
2. **表头有样式**：粗体 + 填充 + 与正文可区分。
3. **加自动筛选**：`ws.auto_filter.ref = ws.dimensions`。
4. **列宽按内容算**，不要留一堆默认 8.43 的窄列让读者自己拖。

数据 sheet 里**不要有合并单元格、不要有小计行混在明细里、不要有脚注行**——
你在 `dirty-data.md` 里骂过的那些脏法，别自己造一遍交出去。

## 八、验收

```bash
python3 scripts/verify_xlsx.py 交付物.xlsx     # 退出码 1 = 有 FAIL
```

它机械地拦这几类：行高装不下 wrap 后的文本、数值列宽不足会显示成 `####`、
未合并的长文本右边有内容会被挡、合并区域吃掉了非空单元格、
浮点没设 `number_format`、冻结窗格落在空行上、同级标题字色不一致。

**和其他三道闸门一样，跑完仍要自己打开看一眼。**
机器判「有没有被裁切」，判不了「这份表读起来顺不顺」。

**没有条件打开 Excel 时**，用 LibreOffice 转一张 PDF 或 PNG 再看：

```bash
soffice --headless --convert-to pdf 交付物.xlsx
```

装不上就明说「本次 xlsx 未做视觉自检」，
不要因为闸门全绿就当作看过了——闸门查的是可测量的错，不是全部的错。

## 九、不要长成这样

对应 `report-styles.md` 第五节，xlsx 特有的默认倾向：

1. **整份报告挤在 B 一列里**，靠溢出往右显示
2. **行高从 `16 / 30 / 45` 里挑**，而不是按内容算
3. **零填充色**，全靠字色做层级，一屏扫下来主次是平的
4. **数值直接扔进单元格**不设 `number_format`
5. **给正文段落画满四边框线**，长得像九十年代的财务模板
6. **每个 sheet 都叫 `Sheet1` / `Sheet2`**，或者叫 `数据`——
   sheet 名是导航，写「客户分层明细」不写「数据」
7. **把 HTML 报告的文字整段复制进单元格**——xlsx 的一格装不下一屏的话，
   该拆成几行，或者干脆承认这部分只适合 HTML
8. **网格线留着**。报告 sheet 关掉（`ws.sheet_view.showGridLines = False`），
   数据 sheet 留着

第 8 条是分界线画得最清楚的一条：**关掉网格线的那一刻，
这张表从「一个电子表格」变成「一份文件」。**
