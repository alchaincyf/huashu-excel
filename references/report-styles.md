# 报告风格

风格是**你的判断，不是用户的选择题**。

拿一堆风格去问「你想要哪种」，是把自己的活推给对方。他要的是一份好报告，
不是一次挑选练习。你看过数据、知道读者是谁、知道这份东西要拿去干什么——
这三件事就足够定风格了。

**但要把判断说出来。** 一句话，说清你选了什么、为什么。
用户看到理由才知道你不是随手挑的，不同意也能一句话改掉。

---

## 出声思考：三个问题定风格

**一、这份东西要拿去做什么？**

| 用途 | 说明 |
|---|---|
| 支撑一个决策 | 有人要拿它拍板 → 结构化、编号、结论前置 |
| 汇报交差 | 对上或对外 → 正式、可打印、经得起细看 |
| 自己或团队看 | 内部快看 → 越轻越好，别装 |
| 讲一个观点 | 有立场要传播 → 叙事性、有态度 |

**二、读者是谁，他有多少耐心？**

投资人和董事会看结构和数字密度；业务负责人看结论和行动项；
工程和产品团队看得懂图但讨厌废话；外部客户会注意你的做工是否体面。

**三、内容本身是什么形状？**

数字密集、多张表 → 高密度风格；
一个核心结论 + 少量证据 → 极简；
需要一路讲下来的逻辑链 → 叙事型。

回答完，风格基本自己浮出来了。

### 示范

> 这是给区域负责人看的季度复盘，要拿去开会拍预算。数字不算多，
> 但结论之间有因果链，需要一张张图铺过去。所以我选 `consulting`——
> Exhibit 编号能让开会时「翻到第 3 张图」这件事成立，图题写结论
> 也正好匹配「开会时只念标题就能过一遍」的场景。

> 这是财务对账的结果，二十几张表、上千个数字，读者是财务总监，
> 他会逐行核。用 `bank`——高密度、等宽数字、行间距压紧，
> 让他一屏能看更多行，斑马纹帮他不串行。

> 这是给我自己看的周度数据，就一个结论。`minimal`。
> 花时间在版式上不如花在多挖一层。

## 内置六种

每种取自一类机构的设计语言。真正的区别不在配色，在**结构**。

### `consulting` — 咨询公司

深海军蓝，标题下粗蓝线，H2 带左侧色条，KPI 卡顶部色条。
**结构特征：自动给每张图编号 Exhibit N，图题写结论而非主题。**

Exhibit 编号不是装饰——它让「翻到第 3 张图」在会议室里成立，
也让报告可以被逐条引用。

适合：战略分析、框架评估、董事会材料、要拿去开会逐页过的东西。

### `bank` — 投行研究报告

深蓝，正文更小更紧，表格 13px、行高压紧、偶数行斑马纹，等宽数字。
版心加宽到 920px 以容纳更多列。

适合：财务建模、估值、对账、尽调、任何「读者会逐行核」的场景。

### `editorial` — 财经媒体

三文鱼粉底色，衬线标题与衬线导语，版心收窄到 760px，正文放大到 16.5px。
窄栏 + 衬线是给「从头读到尾」设计的。

适合：行业观察、深度解读、有观点的长报告。

### `magazine` — 杂志式

白底，标题上方一道红块，H2 前红色短横，图题前红色小方块。版心 740px。
红色只出现在标识性元素上，不用于数据。

适合：观点报告、行业洞察、有立场的分析。

### `product` — 科技公司

12px 圆角卡片，浅蓝灰底，紫蓝强调，大量留白，图表整体装在卡片里。

适合：产品复盘、增长分析、内部评审、给互联网团队看的东西。

### `minimal` — 极简

无边框、无卡片、KPI 直接裸排，版心 720px。

适合：内部快看、单一结论、只想把数说清楚。

## 都不合适：自己配

内置六种是常见场景的快捷方式，不是围栏。
遇到品牌色要求、特殊场景、或者你就是觉得都不对，直接给 `custom_style`：

```json
{
  "style": "minimal",
  "custom_style": {
    "bg": "#0F1115", "fg": "#F2F4F8", "muted": "#8A94A6",
    "rule": "#252A33", "card": "#171B22", "accent": "#4CC38A",
    "pos": "#4CC38A", "neg": "#E5484D",
    "exhibit": false,
    "extra_css": ".wrap{max-width:900px} h1{letter-spacing:-.03em}"
  }
}
```

`style` 提供底子，`custom_style` 覆盖在上面。可覆盖的字段：
`bg` `fg` `muted` `rule` `card` `accent` `pos` `neg` `h_font` `b_font`
`extra_css` `exhibit`。

`extra_css` 里可以用 `%(accent)s` 这类占位引用当前配色。

**做深色主题时**注意：图表的 SVG 用的是同一套颜色变量，
`rule` 太暗参考线会消失，`muted` 太暗刻度看不清。改完自己开一眼。

## 不管什么风格，这几条不变

**标题写结论。** 「华东贡献六成销售额但增速垫底」，不是「销售额分析」。
这条对报告标题、章节标题、图表标题一律适用。

**口径声明在正文之前。** 没有口径的数字没法被检验。脚本会在缺失时警告。

**边界声明在末尾。** 数据覆盖到哪、哪个结论最脆弱、什么没验证。
一份说出了自身弱点的报告，比一份天衣无缝的报告可信。

**图表遵守诚实性约束。** 柱形从 0、类别按值排序、坐标轴用整刻度、
不完整的末期画虚线。详见 `charts.md`。

**颜色不表达判断。** 红绿只用在明确的正负数值上（`pos`/`neg`），
不要用颜色暗示「这个渠道不好」——那是你的结论，该写在文字里，
让读者知道那是判断而不是数据。

## 视觉之外

风格决定这份报告长什么样，但决定它有没有用的是内容。

一份配色完美、排版精致、结论全是「A 占比 44%」的报告，
不如一份纯文本但说清了「所以预算该往哪挪」的备忘录。

洞察怎么挖、多视角怎么选、结论怎么组织，见 `insight-report.md`。
先把那个做到位，再来挑风格。
