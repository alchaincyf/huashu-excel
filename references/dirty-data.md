# 脏数据的形态与修法

数据分析的时间有多达 80% 花在清洗上（Wickham, *Tidy Data*）。
这份文件是那 80% 的地图。

目标形态是 **Tidy Data** 三原则：
每个变量一列，每条观测一行，每类观测单位一张表。

---

## 一、Tidy Data 的五种经典脏形态

Wickham 在论文里归纳的五类，加上对应手法。绝大多数脏表是这五类的组合。

### 1. 列名是「值」而不是变量名

```
门店      2024      2025      2026
朝阳店    120       150       180
```

年份是「年份」这个变量的取值，却被摊成了列名。这种表没法按年份筛选、
没法做时间序列，加一年就要改一次分析代码。

**修法：宽转长（melt）**

```python
long = df.melt(id_vars=["门店"], var_name="年份", value_name="销售额")
```

反向操作（长转宽 pivot）用于最终呈现——分析时用长表，给人看时转宽表。

### 2. 一列里塞了多个变量

```
标签
北京-华北-直营
上海-华东-加盟
```

一个格子里有城市、大区、经营模式三个变量。想按大区汇总就得字符串截取，
一旦有个值写成「北京—华北—直营」（破折号不同）就全错。

**修法：拆列（split）**

```python
df[["城市", "大区", "模式"]] = df["标签"].str.split("-", expand=True)
```

拆完必须验证：`df["模式"].value_counts()` 看有没有意外的取值——
分隔符不统一的行会拆出错位的结果，而且不报错。

### 3. 变量同时存在于行和列

```
门店      指标        1月     2月
朝阳店    销售额      120     150
朝阳店    客户数      80      95
```

「指标」在行方向，「月份」在列方向。这种表做任何计算都得同时处理两个方向。

**修法：先全部融成长表，再按需要 pivot 回去**

```python
long = df.melt(id_vars=["门店", "指标"], var_name="月份", value_name="值")
tidy = long.pivot_table(index=["门店", "月份"], columns="指标",
                        values="值", aggfunc="first").reset_index()
```

### 4. 多种观测单位混在同一张表

订单明细里混着客户属性：

```
订单号  金额   客户名  客户注册日  客户等级
A001    120    张伟    2024-01-05  VIP
A002    80     张伟    2024-01-05  VIP
```

客户信息随订单重复。改一次客户等级要改 N 行，必然出现同一个客户两种等级。

**修法：拆成两张表，用键关联**

```python
orders = df[["订单号", "金额", "客户名"]]
customers = df[["客户名", "客户注册日", "客户等级"]].drop_duplicates()
# 关键验证：拆完客户表应该每个客户只有一行
assert customers["客户名"].is_unique, "同一客户有多种属性，先查清哪个对"
```

那个 assert 经常会失败。失败就是收获——你发现了一个一直存在的数据矛盾。

### 5. 同一种观测单位拆在多张表

一月表、二月表、三月表，或者一个门店一个 sheet。

**修法：纵向合并，并且加一列记录来源**

```python
sheets = pd.read_excel(f, sheet_name=None)      # 全部 sheet
all_df = pd.concat(
    [d.assign(来源=name) for name, d in sheets.items()],
    ignore_index=True,
)
```

那个 `来源` 列不能省。合并之后出现异常值时，它是唯一能让你定位到哪张表出问题的线索。

**合并前必须核对列名是否一致**：

```python
cols = {name: tuple(d.columns) for name, d in sheets.items()}
if len(set(cols.values())) > 1:
    for name, c in cols.items():
        print(name, c)          # 列名不一致，concat 会静默产生一堆 NaN 列
```

## 二、中文办公场景特有的形态

这部分在英文文献里基本没有，但在中国的表里是常态。

### 表头不在第一行

第 1 行是标题（还合并了单元格），第 2 行是「制表：财务部」，第 3 行才是真表头。
`pd.read_excel()` 会把标题当列名，其余列变成 `Unnamed: 1..N`。

**识别**：跑体检脚本，它会给出 `header=` 该填什么。

**修法**：`pd.read_excel(f, header=2)`（0-based）

### 两级或多级表头

```
        |        一季度         |
地区    | 1月   | 2月   | 3月   |
```

「一季度」跨列合并，只有左上角有值。

**修法**：`pd.read_excel(f, header=[2, 3])` 得到 MultiIndex 列名。

拍平时**继承必须限制在合并范围内**。无脑向右填充会把「3月」一路传给右边所有列，
让「上半年合计」变成「上半年合计 / 3月」。体检脚本用 openpyxl 的合并范围做边界，
不用向右填充。

### 分组标签用合并单元格表达

```
地区      门店
华北      朝阳店      ← A2:A4 合并
          海淀店
          和平店
华东      静安店
```

pandas 只保留左上角，其余行是 NaN。

**修法**：`df["地区"] = df["地区"].ffill()`

**绝对不能 `dropna()`**——那会把每个分组除第一行以外的所有行删掉，
而且删得干干净净不留痕迹。这是「静默丢一半数据」的头号原因。

### 汇总行混在明细里

尾部有「合计 / 占比 / 同比」，中间还有「华东小计」。求和时把它们算进去，
结果直接翻倍，而且不报错。

**识别**：行首或首列标签含「合计、总计、小计、汇总、累计、占比、同比、环比、平均」。
注意关键词**经常在词尾**（「华东小计」「全国合计」），用 `startswith` 会漏掉大半。

**修法**：排除这些行。但**先别删** ——
它们是免费的校验和，拿明细求和去对它们（见对账脚本）。对完再排除。

### 数字被存成文本

带千分位逗号（`1,234,567`）、货币符号（`¥1200`）、单位后缀（`332.68万元`）、
括号负数（`(1,200)` 表示 -1200，会计惯例）、前面有个单引号。

**症状**：`df["金额"].sum()` 得到 0，或者变成一个超长的字符串拼接。
`dtype` 显示 `object` / `str`。

**修法**：

```python
def to_num(s):
    s = (s.astype(str)
           .str.replace("　", "", regex=False)     # 全角空格
           .str.strip()
           .str.replace(r"^\((.*)\)$", r"-\1", regex=True)   # 括号负数
           .str.replace(r"[,，¥￥$]", "", regex=True)
           .str.replace(r"(万元|亿元|千元|万|亿|元|个|人|次|件|台)$", "", regex=True))
    return pd.to_numeric(s, errors="coerce")
```

**转完必须核对转失败的数量**：

```python
n = to_num(df["金额"]).isna().sum() - df["金额"].isna().sum()
print(f"{n} 个值转不成数字")     # 不为 0 就去看是哪些，别放过
```

静默的 `errors="coerce"` 是很多错误的入口——它把转不了的变成 NaN，
然后 `sum()` 自动跳过 NaN，于是你少算了一批数据却毫无感觉。

### 单位混用

同一列一半是「元」一半是「万元」，或者列名写「万元」而值其实是元。

**识别**：看中位数量级和列名声明是否相符。列名写万元、中位数却是七位数，就是错的。
对账脚本会报这一项。

**修法**：没有自动解法，必须问清楚。这是典型的「机器判不了、交给人」。

### 缺失值伪装成文字

`—`、`--`、`N/A`、`无`、`暂无`、`/`、`空`、`待定`、`?`

pandas 不认得这些，会当成正常字符串，于是这一列变成文本列，
所有数值运算失效，而 `isna().sum()` 报 0 个缺失。

**修法**：读的时候就声明

```python
NA = ["-", "--", "—", "——", "/", "N/A", "NA", "无", "空", "暂无", "待定", "?", "？"]
df = pd.read_excel(f, na_values=NA, keep_default_na=True)
```

### 日期的四种写法混排

`2026/1/5`、`2026年1月12日`、`45689`（Excel 序列号）、`1月8日`（缺年份）。

**Excel 序列号**：1900 日期系统下，整数表示从 1899-12-30 起的天数。
落在 32874–73051 区间（约 1990–2100 年）的整数，很可能是日期被存成了数字。

```python
pd.to_datetime(df["日期"], unit="D", origin="1899-12-30")   # 序列号转日期
```

**缺年份的**（`1月8日`）：跨年数据会错序，必须先确认年份再补。

**修法**：分类处理而不是一把 `to_datetime`

```python
d = pd.to_datetime(df["日期"], errors="coerce", format="mixed")
未解析 = d.isna() & df["日期"].notna()
print(df.loc[未解析, "日期"].unique())     # 看剩下的是什么形态，逐类处理
```

不要用 `dayfirst` 猜——`03/04/2026` 是 3 月 4 日还是 4 月 3 日，
猜错了不会报错，但整个时间序列会错位。去问。

### 空格制造幽灵分组

「张伟」和「张伟 」（尾随半角空格）、「张伟　」（全角空格 U+3000）
在 `groupby` 里是三个人。

**识别**：

```python
s = df["销售员"]
print(len(s.unique()), "→", len(s.astype(str).str.replace("　","").str.strip().unique()))
```

两个数字不同，就有幽灵分组。

**修法**：`s.astype(str).str.replace("　", "").str.strip()`

同类问题还有：大小写（`ABC` / `abc`）、简繁体、中英文括号、
中英文逗号、不同的破折号（`-` `–` `—` `─`）。

### 隐藏行列

隐藏往往意味着「有意排除」——上一个人故意不让它进统计。
pandas 读不到「隐藏」这个属性，会全部读进来。

**识别**：体检脚本会列出隐藏行列（用 openpyxl 读 `row_dimensions[r].hidden`）。

**修法**：不要自己决定。问清楚为什么隐藏，再决定纳不纳入。

## 三、清洗的三条纪律

**可回放。** 用脚本清洗，不手工改单元格。别人要能复现你的每一步，
你自己也要能在三个月后说清第 47 行为什么被删了。

**留痕。** 每一步记下影响了多少行。

```python
before = len(df)
df = df[df["金额"].notna()]
print(f"删除金额缺失：{before} → {len(df)}（-{before-len(df)}）")
```

清洗完总行数变化必须能被完整解释。解释不了的差额就是 bug。

**不静默。** `errors="coerce"`、`dropna()`、`fillna(0)` 都会安静地改变结果。
每次用完都要报告影响了多少行。用 `fillna(0)` 尤其危险——
缺失和 0 是两件事，把「没数据」填成「值是 0」会把均值直接拉低。
