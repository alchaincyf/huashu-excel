# 洞察与报告

数据报告最常见的失败不是分析不够深，是**把描述当成了洞察**。

---

## 一、什么算洞察

**洞察是能改变某人某个决定的东西。** 改变不了任何决定的，无论多准确、多详尽，
都只是描述。

三个层次，大多数报告停在第一层：

| 层次 | 例子 | 读者的反应 |
|---|---|---|
| 描述 What | 华东销售额 6497 万，占比 44% | 「哦。」 |
| 诊断 Why | 华东占比高是因为门店密度大，但单店产出低于华南 | 「有点意思。」 |
| 含义 So what | 华东是存量盘不是增长盘，新增预算应该投华南 | 「那我得改一下预算。」 |

**每条洞察出手前过三个问题：**

1. 它能改变什么决定？答不上来就删掉，或者往下挖一层
2. 如果结论是反的，读者会做不同的事吗？不会，就说明这个维度不重要
3. 有没有可能是数据错的？（Twyman's Law）——特别漂亮的结论先回去查数据

第 3 条不是形式。一份报告里最吸引人的那个发现，恰恰是最可能来自脏数据的那个。

## 二、多视角分析

同一份数据，不同视角看出不同东西。分歧处信息量最大。

### 视角怎么选：认知距离最大化

**不要按领域相近来凑。** 「财务分析师 + 会计」是同一个脑子的两个名字，
产出高度重叠，等于白跑一遍。

要挑思维方式互相拉扯的组合。一份销售数据的三个视角：

| 视角 | 只关心 | 会问的问题 |
|---|---|---|
| 增长 | 哪里还有空间 | 哪个渠道的天花板还没碰到？边际投入产出比最高的是谁？ |
| 风险 | 哪里会塌 | 收入集中在几个客户身上？丢掉最大的一个会怎样？ |
| 效率 | 投入产出比 | 单位成本产出多少？哪块业务在补贴哪块？ |

三个视角对同一组数字会给出不同的建议方向，而且经常互相矛盾。
**矛盾不是要消除的，是要呈现的**——「增长视角建议加码华南，风险视角指出华南
三个客户占了 70% 收入」，这个张力本身就是决策者最需要知道的东西。

其他常用组合（按数据类型选，每次挑 3 个，别超过 5 个）：

- 投放/电商：增长 / 成本效率 / 用户行为 / 供给能力
- 财务：盈利质量 / 现金流 / 风险敞口 / 同业对比
- 运营：流程瓶颈 / 质量 / 成本 / 一线可执行性
- 产品：留存 / 转化 / 分群差异 / 竞品位置

### 怎么执行（按你的环境档位）

**并行档**：每个视角派一个独立子任务，各带完整的数据上下文和该视角的定义，
互相不看对方的结论。全部回来后再综合。

**串行档**：你自己依次切换。规矩是——
每个视角开始前明确声明「我现在只从 X 角度看，其他角度先不管」，
写完这个视角的完整结论再切下一个，**中途不要综合**。
三个都写完，再回头找分歧。

提前综合是串行档唯一的陷阱：第一个视角的结论会污染后两个，
最后三个视角说的其实是同一件事。

### 综合时做什么

不是取平均，也不是把三段拼起来。

1. **先找分歧**——三个视角结论不一致的地方，逐条弄清楚为什么不一致
2. **不一致往往说明有隐藏变量**（华南增速快是因为基数小，还是真的更好？）
3. **按主题重组，不按视角重组**——最终报告里不出现「增长视角认为…」
   这样的措辞，读者不关心你怎么分工的
4. 保留有价值的张力，不要为了结论统一而抹平

## 三、报告结构

用 Barbara Minto 在麦肯锡建立的金字塔原理：**结论在顶，论据在下，证据在底**。

### 开头用 SCQA

| | 写什么 | 例 |
|---|---|---|
| S 情境 | 双方都同意的事实 | 上半年整体销售额 1.47 亿，完成年度目标的 48% |
| C 冲突 | 打破平静的那件事 | 但三月起连续四个月环比下滑 |
| Q 问题 | 由此产生的问题 | 下滑是普遍的还是局部的？ |
| A 答案 | **你的结论，直接给** | 下滑集中在华东三家门店，其余区域仍在增长 |

A 就是全文的主论点。**它出现在第一段，不是最后一段。**
报告不是推理小说，读者没有耐心陪你从头推到尾。

### 主体用 MECE 分组

支撑论点的几个理由必须**互相不重叠、合起来无遗漏**（Mutually Exclusive,
Collectively Exhaustive）。

重叠的表现：两个小节讲的是同一件事换了说法。
遗漏的表现：读者能立刻想到一个你没提的可能性。

分组维度要一致——不能一个按地区分、一个按渠道分、一个按时间分混在一起。

### 结尾

给 3–5 条可执行的建议，按优先级排。
「需要进一步研究」不是建议，那是没做完。

如果确实数据不足以给建议，就直说「这个问题现有数据回答不了，
需要补 X 数据」——这比编一条空建议诚实，而且对读者更有用。

## 四、措辞：证据强度决定语气

| 你有的证据 | 能说 | 不能说 |
|---|---|---|
| 单期观察 | 「这段时间里 A 高于 B」 | 「A 比 B 好」 |
| 多期一致 | 「A 持续高于 B」 | 「A 导致了…」 |
| 有对照实验 | 「A 带来了 X% 提升」 | 「A 一定会…」 |
| 相关分析 | 「X 与 Y 同向变动」 | 「X 提升了 Y」 |

**样本小于 30 时，任何百分比都要同时给绝对数。**
「增长 200%」在基数是 2 的时候是四个人的事。

**不确定就把不确定写进句子。**
「大概率是渠道 C 的问题，但我只有两周数据，换个窗口可能就不成立」——
比「渠道 C 是主要问题（注：样本有限）」诚实得多。
免责声明放在括号里等于没说，读者只会记住主句。

**口径跟着数字走。** 每个关键数字后面注明口径，或者在报告开头统一声明。
一份没有口径声明的报告，里面的数字全都无法被检验。

## 五、说出你的 BUT

写报告的过程中，你心里一定会冒出这类念头：

- 「这个结论其实挺勉强的」
- 「样本太少了但看起来还行」
- 「这个数我没验过」
- 「换个切法结论可能相反」

**立刻写出来，不要憋着。**

模型憋着不说的倾向很强。而对读者来说，一份说出了自身弱点的报告，
比一份看起来天衣无缝的报告可信得多——因为前者可以被检验，后者只能被相信。

具体做法：在报告末尾固定加一节「这份分析的边界」，写清楚：
数据覆盖的时间范围、哪些没有验证、哪个结论最脆弱、换什么口径会翻盘。

## 六、报告形态

按读者和用途选，不要默认做最重的那个。

| 读者要什么 | 给什么 |
|---|---|
| 快速知道结论 | 一段话 + 一张图。多数情况这就够了 |
| 要自己下钻 | 干净的 Excel + 透视表 + 几个关键图表 |
| 要拿去汇报 | 结构化报告（HTML/文档），结论先行 |
| 要定期看 | 一个能刷新的 Excel 模板，而不是一次性报告 |

最后那条经常被忽略：**如果这个分析每月都要做一次，正确的交付物是一个
能一键刷新的模板，不是这个月的报告。** 做模板的时间会在第二个月就赚回来。

图表怎么选、怎么不误导，见 `charts.md`。
